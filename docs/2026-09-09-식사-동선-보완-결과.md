## 구현 결과

- **식사 보완:** 반나절·여유로운 일정의 점심, 하루의 점심·저녁, 1박2일의 1일차 점심·저녁과 2일차 점심을 확인한다. 누락 시 서버가 수집한 실제 음식점 후보를 시간표 빈 구간에 넣는다. 추가할 자리가 없으면 중복된 관광·문화 슬롯 하나를 대체할 수 있으나 핵심 볼거리 최소 한 곳과 기존 카페·식사·축제·숙박은 유지한다.
- **긴 이동 구간 보완:** 인접 구간이 직선 20km를 넘으면 미사용 후보 중 같은 역할의 가까운 장소로 교체를 시도한다. 두 인접 구간이 모두 20km 이내이고 거리 합계가 1km 넘게 줄 때만 반영한다. 장소 순서·방문일·체류시간을 유지하며 숙박·축제는 바꾸지 않는다.
- **운영시간 대조:** 단순 시간대, 준비시간, 마지막 주문·입장 마감을 해석한다. 방문이 해당 시간과 충돌하면 보완 후보에서 제외한다. 계절별·요일별 복합 문장, 자정을 넘는 영업 등 확실히 해석하지 못한 값은 미확인으로 둔다. 기존 방문의 확인 가능한 시간 충돌은 경고한다.
- **접근성 정보 보존:** 보완 식사는 선택 조건의 원문 정보가 있는 후보를 우선한다. 장소를 대체할 때 기존에 원문이 있던 각 접근성 조건을 잃지 않도록 한다. 원문 보유는 이용 가능 판정이 아니다.
- **결과의 설명 정합성:** 변경된 장소·시간에 맞지 않을 수 있는 이전 설명·팁·전체 스토리·예상 비용을 제거하거나 조정 안내로 바꾼다. 결과 화면에서 보완한 장소와 이유를 표시하고, 삭제된 장소의 보완 기록은 표시하지 않는다.

보완에 새 AI 호출이나 새 관광 API 호출을 추가하지 않았다. 기존에 수집해 둔 예비 후보를 서버에서 사용한다. AI 응답은 먼저 **AI에게 실제로 제공한 목록**에 대해 원본 대조를 통과해야 한다. 예비 후보를 AI가 임의 선택해도 허용하지 않는다.

주요 코드: `lib/course-repair.ts`, `lib/operating-window.ts`, `lib/course-timing.ts`, `lib/course-quality.ts`, 생성 API, `CourseEvidence.tsx`. 프롬프트의 사실·조건 우선 원칙과 구성 재시도 기본 꺼짐 정책은 유지했다. 설명 지시를 강화하는 것만으로 식사 누락을 해결했다고 간주하지 않고 서버 검증·보완을 함께 적용했다.
