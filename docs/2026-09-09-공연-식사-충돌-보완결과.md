- 이전: 11시 수문장 교대의식 → 전시 → 점심 → 청계광장 → 카페 → 18시 덕수궁 밤의 석조전. 저녁이 없고 마지막 공연 체류는 60분이었다.

- 결과 화면에 ‘축제 대신 식사 보완’과 교체 전 축제명을 표시한다. 이미 예약한 개인 일정이나 사용자가 따로 지정한 공연을 수정하는 기능은 아니다. 이번 로직은 서버가 자동 생성한 코스 초안에 적용한다.

## 2. 수정 내용과 경계

### 행사시간 파서

`lib/festival-timing.ts`는 원문 전체가 지원 문법에 맞을 때만 판정한다.

- 단일 운영 구간, 명시적 시작 시각 목록, `매주 토요일` 같은 단일 요일, `※ 매주 월요일 휴무`, `회차당 100분`을 지원한다.
- `11:00 / 14:00`은 시작 시각 목록이다. `18:00~20:55`는 운영 구간이며, 두 끝점을 회차로 만들지 않는다.
- 운영 구간의 길이를 필수 체류시간으로 만들지 않는다. 회차당 소요시간이 명시된 경우에만 부족한 체류시간을 늘린다. 이미 긴 체류를 줄이지 않는다.
- 계절별 시간, 특정 날짜 예외, 시간 미정, 익일 종료, 서로 모순되는 조건 등은 **미확인**으로 남긴다. 일부만 읽어서 확정하지 않는다.
- 요일이 분명하게 맞지 않는 축제는 배정된 날짜에서 제외하며 다른 날짜로 넘기지 않는다.

### 일정 보완

`course-festival.ts`·`course-timing.ts`·`course-quality.ts`에서 처리한다.

1. 원본 대조 → 방문일/요일 검사 → 긴 이동 구간 보완.
2. 원본에 명시된 회차당 체류시간 반영.
3. 일반 장소의 겹치는 시간을 보완하되 **축제 시작을 임의로 늦추지 않음**.
4. 명시된 시작 시각 목록이 있으면 앞뒤 일정·이동 추정·일차·시간 예산 안에 들어가는 시각만 선택. 맞는 시각이 없으면 기존 제안과 충돌 경고를 남김.
5. 식사 보완 → 최종 원본·구성·시간 검사. 시각·장소가 바뀌면 예전 설명·비용·전체 이야기를 검증 없이 유지하지 않음.

원문 시간 조건 일치와 실제 개최·예약 가능은 구별한다. 소요시간만 알고 회차별 시작을 모르는 경우에는 별도의 미확인 문장을 보여준다.

### 식사와 겹치는 중복 축제

`course-repair.ts`의 우선순위는 **빈 구간에 식사 삽입 → 중복 관광 슬롯 대체 → 식사와 겹치는 중복 축제 대체**다.

마지막 단계는 같은 일차에 축제가 2개 이상일 때만 적용하며 최소 하나를 남긴다. 실제 예비 음식점 후보가 영업·휴무·거리·이동·일차·시간 예산 조건 안에 들어가야 한다. 가능한 식당이 없으면 축제를 삭제하지 않고 부족한 식사와 시간 충돌을 경고한다. 숙소·카페를 식당으로 바꾸지 않으며, 이 단계에서 추가 API/AI 요청은 없다.

### 프롬프트·결과 UI

- 공연 회차·요일·체류시간을 우선하고, 충돌하면 선택 축제 수를 줄이도록 지시했다. 식사를 빼거나 공연을 임의로 늦추거나 예산을 늘려 맞추지 않는다.
- 기존의 ‘현지인만 아는’·‘개화 절정’ 예문이 사실성 우선 지시와 상충하여, 확인된 특성과 사용자 조건을 연결하는 예문으로 바꿨다.
- `CourseEvidence`에 공연 시간 보완 / 축제 대신 식사 보완을 구분해 표시하고 교체 전 축제명을 함께 보여준다. 사라진 장소의 보완 배지는 숨긴다.
