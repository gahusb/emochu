## 0. 시작 전 — 5분이면 끝나는 준비 3가지

### ① 규격을 고정한다 (가장 중요)

기존 2장이 **1320 × 2868** 이다. **모바일 세로**이고, 논리 해상도 **440 × 956 · DPR 3** 과 일치한다.

> 🔑 **Chrome 개발자도구 → 디바이스 툴바(Ctrl+Shift+M) → Responsive → 440 × 956, DPR 3**
> 이렇게 고정하면 **매번 같은 규격**이 나오고, 다음에 다시 찍어도 어긋나지 않는다.

캡처: 개발자도구 **⋮ → Capture screenshot**(보이는 영역) / **Capture full size screenshot**(페이지 전체).

- 🔴 **6장 전부 같은 규격으로 통일한다.** 섞이면 PDF에서 정렬이 무너진다.
- 세로 스크롤이 긴 화면(홈·코스 결과)은 **full size** 가 낫다.

### ② 코스를 하나 만들고 **URL을 메모한다**

코스 결과는 `/course/[slug]` 로 **저장된 코스를 다시 불러온다**(`/api/course/[slug]`).

> 🔑 **좋은 코스가 나오면 그 URL을 반드시 적어 둔다.**
> AI 생성이라 매번 달라지는데, **slug URL이 있으면 같은 코스를 언제든 다시 연다.**
> 재촬영·수정본 제출·발표자료까지 전부 이 URL 하나로 해결된다.

```
메모해 둘 것
  코스 A (일반)     https://emochu.vercel.app/course/________
  코스 B (무장애)   https://emochu.vercel.app/course/________
```

### ③ 화면에서 지워야 할 것

| 확인 | 왜 |
|---|---|
| 🔴 **실제 집 주소·상세 좌표가 안 보이는가** | GPS 「내 주변」으로 만들면 출발지가 집이 된다 → **도시 선택으로 만들 것** |
| 🔴 브라우저 확장·북마크바·개인 계정 표시 | **시크릿 창**에서 찍으면 한 번에 해결 |
| 🟡 개발 중 표시(콘솔 경고 배너 등) | 배포본(`emochu.vercel.app`)으로 찍는다. 로컬 아님 |

## 1. 찍을 컷 6장 — 무엇을·어떻게

### 📸 대표 (1장) — 코스 결과 「타임라인 + 지도」

**이 한 장이 서비스를 설명해야 한다.** 심사위원이 제일 먼저 본다.

| | |
|---|---|
| **URL** | `/course/[slug]` (위에서 메모한 코스 A) |
| **담을 것** | 시간순 코스 카드 + **카카오맵 마커**가 **한 화면에** |
| **확인** | 관광지·맛집·카페·축제·숙박 **5색 구분**이 보이는가 · 이동 시간/거리가 보이는가 |

> 💡 **코스에 4~5곳이 들어간 것**을 고른다. 2곳짜리는 빈약해 보이고, 8곳은 잘린다.
> 💡 **축제가 하나 끼어 있는 코스**면 더 좋다 — TourAPI 활용 폭이 한눈에 보인다.

| | |
|---|---|
| **URL** | `/` |
| **담을 것** | 주말 날씨 · 진행 중인 축제 · AI 코스 추천 카드 |
| **기존 파일** | `docs/images/emochu_home.png` (5월 촬영) |

### 📸 상세 ② — 축제 매거진

| | |
|---|---|
| **URL** | `/festival` |
| **담을 것** | 4단계 상태 뱃지(**진행 중 · 이번 주말 · 곧 시작 · D-Day**)가 섞여 보이는 그리드 |

> 🔴 **뱃지가 한 종류만 보이면 다시 찍는다.** 4단계 구분이 이 화면의 요점인데, 전부 「진행 중」이면 기능이 안 보인다. 스크롤해서 **섞여 있는 구간**을 잡는다.

---

### 📸 상세 ③ — ⭐ 무장애 맞춤 코스 **(반드시 넣을 것)**

**이 서류에서 가장 강한 차별점이다.** 글로만 쓰면 심사위원이 지나친다.

| | |
|---|---|
| **만드는 법** | `/course` → 6단계 위저드에서 **접근성 스텝(마지막)에 「이동」 선택** → 생성 |
| **담을 것** | 코스 카드에 붙은 **무장애 정보 원문** |

🔑 **이 컷의 요점 — 원문이 그대로 보여야 한다.**

이 서비스의 무장애 표시는 `✅ 휠체어 가능` 같은 **한 줄로 접지 않는다.** 코드 주석이 그 이유를 이렇게 적어뒀다:

> *"주출입구는 경사로가 있어 휠체어 접근 가능함"과 "후문에만 경사로 있음"은 전혀 다른 정보인데, boolean으로 접으면 둘이 같아진다."*

→ **문장이 길게 나오는 장소**를 고른다. 짧으면 이 설계가 안 보인다.

> ⭐ **「미확인」 표시가 같이 보이면 오히려 좋다.**
> 접근성 조건을 골랐는데 원본 데이터가 없으면 **서버 판정으로 "미확인"** 을 띄운다 — *"생성형 문장이 아니라 서버 판정으로 경고해야 사용자가 그럴듯한 설명을 사실로 오해하지 않는다"* (코드 주석).
> **AI가 지어내지 않는다는 증거**라, 하이브리드 아키텍처 차별성과 그림이 맞는다.

🟡 **지금 찍을지는 보류를 권한다.** 사주는 현재 위저드 안에 **접혀 있어** 노출도가 낮다.

→ **제출은 9/21까지 수정 가능**하므로, 1차 제출은 ①~④ + 대표 **5장**으로 내고 이건 나중에 추가해도 된다.

### 📸 (권장) 출처 표기가 보이는 컷 1장

🔴 **규정 준수의 시각 증거**다. 어느 컷이든 **푸터의 `출처: ⓒ한국관광공사`** 가 한 번은 보이게 한다.

- 홈이나 코스 결과를 **full size**로 찍으면 푸터가 자연히 들어간다
- ❌ **`TourAPI` 단독 표기**로 보이면 규정 위반 — 그 경우 촬영 전에 **문구를 먼저 고친다**(`app/components/nav/SiteFooter.tsx`)
- ❌ 공식 CI/BI **로고 이미지**는 불가. **텍스트만**

> ⚠️ 자동 검사는 **문자열 존재만** 확인했다(`SiteFooter.tsx:12`). **실제 렌더링은 눈으로 봐야 한다** — 이번 촬영이 그 확인을 겸한다.

## 2. 찍은 뒤 — 정리

### 파일 크기를 줄인다

기존이 **장당 3.7MB** 다. 6장이면 **22MB** 이고, PDF에 넣으면 업로드가 버거워진다.

> **가로 1320px 유지 · PNG 최적화 또는 품질 85 JPG** → 장당 **300~800KB** 면 충분하다.
> 화질은 인쇄가 아니라 **화면 심사** 기준이면 된다.

### 파일명·위치

```
docs/images/
  submit_01_cover_course.png       ← 대표: 코스 결과
  submit_02_home.png               ← 상세①
  submit_03_festival.png           ← 상세②
  submit_04_barrierfree.png        ← 상세③ ⭐
  submit_05_spot_detail.png        ← 상세④
  submit_06_saju.png               ← 상세⑤ (나중)
```

> 🔴 **`loops/submission-check/assets/` 에는 기능설명서 PDF를 넣는다.** 이미지 항목도 같은 폴더를 보므로, 최종 이미지를 여기에 함께 두면 `check.mjs` 가 ✅ 로 바꾼다.
> 확인: `node loops/submission-check/check.mjs`
