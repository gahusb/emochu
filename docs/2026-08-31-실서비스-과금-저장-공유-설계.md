## 1. 과금 — 「무료 + 일일 상한 + 예산 차단기」

### 왜 이 방식인가

공모전 심사 기간에 **심사자가 막히면 안 된다.** 로그인 게이트는 마감 3주 전에 도입하기엔
리스크가 크고, 무제한 개방은 상한 없는 청구서가 된다. 그래서 **문은 열어두되 천장을 둔다.**

### 두 겹 + 원래 있던 한 겹

| 겹 | 무엇을 막나 | 어디 |
|---|---|---|
| 분당 3회 (인메모리) | **버스트** | `app/api/course/route.ts` `checkRateLimit` (기존) |
| 개인 일일 N회 | 한 사람의 반복 | `lib/usage-limit.ts` |
| **전체 일일 N회** | **하루 최대 지출** | `lib/usage-limit.ts` |

🔴 기존 분당 리미터는 **버스트 차단기지 예산 차단기가 아니다.**
서버리스라 인스턴스마다 Map 이 따로 살고 콜드스타트마다 리셋되며, 무엇보다
**하루 총량 개념이 없다** — 분당 3회를 하루 내내 유지하면 4,320회 ≈ 13만원이다.

전체 상한이 핵심이다. 개인별만 두면 IP 를 바꿔가며 우회할 수 있어 상한이 상한이 아니다.

### 설계 결정

- **카운터 저장소는 Supabase.** 서버리스에서 in-memory 는 인스턴스마다 흩어져 아무것도 못 막는다.
  Redis 는 이 프로젝트 인프라에 없다.
- **증가는 원자적으로**(`wk_bump_usage` RPC). `select → +1 → update` 로 나누면 동시 요청에서
  카운트가 새고, 그러면 상한이 상한이 아니게 된다.
- **IP 를 그대로 저장하지 않는다.** 필요한 건 "같은 사람인가"뿐이라 `sha256(salt+ip)` 앞 32자만 쓴다.
- **상한 판정은 외부 API 를 부르기 전에.** TourAPI 를 다 부르고 막으면 막은 요청에도 비용이 든다.
- 🔴 **카운터 실패 시 통과시킨다(fail-open).** 심사 기간에 Supabase 가 잠깐 흔들렸다고 서비스가
  멈추는 쪽이, 그 사이 몇 건 더 나가는 쪽보다 나쁘다. 대신 `🔴 예산 차단기 없이 진행 중` 을
  로그에 남긴다 — **조용히 열려 있는 상태를 만들지 않는다.**
- 상한은 **KST 자정**에 풀린다. 429 응답에 `Retry-After` 를 실어 보낸다.

### 운영 파라미터 (환경변수)

| 변수 | 기본값 | 의미 |
|---|---|---|
| `COURSE_DAILY_LIMIT_PER_CLIENT` | 20 | 한 사람당 하루 코스 생성 수 |
| `COURSE_DAILY_LIMIT_GLOBAL` | 500 | **서비스 전체 하루 상한 = 하루 최대 지출** |

| `NEXT_PUBLIC_AUTH_PROVIDER` | `kakao` | `kakao` | `google`. 카카오가 막혀 있는 동안의 우회로 |

## 2. 코스를 어디까지 만들어주나

### 이미 하고 있던 것
제목 · 요약 · `storyArc` · 팁 · 장소별(시간·소요·설명·팁·`hook`·`whyNow`·이동정보·이미지·
무장애 정보·방문일 영업여부) · 총거리 · 예상비용 · 난이도 · 사주 기운

### 이번에 채운 것 — **실행 연결**

「보는 코스」와 「가는 코스」 사이가 비어 있었다. 코스를 다 보고 나면 사용자는
**다시 검색창으로 나가야 했다.** 그래서 장소 카드마다 **길찾기 · 전화** 를 붙였다.

- 길찾기: 카카오맵 `link/to` 에 **좌표까지** 넘긴다 — 이름이 겹치는 곳에서도 정확히 찍힌다
- 전화: 🔴 **목록 API(`locationBasedList2`)의 `tel` 은 빈 값으로 온다**(실측: 음식점·관광지 각
  20건 전부 빈 값). 상세에만 있다. 그런데 파이프라인이 **이미 `detailIntro2` 를 부르고 있어서**
  거기서 건졌다 — **추가 API 호출이 0 이다.**
- 🔴 형태만 보는 정규식은 위험하다. 첫 구현이 `0507-1400-1797` 에서 `07-1400-1797` 을 뽑아
  **못 거는 번호**를 버튼에 붙였다. 지금은 「덩어리를 잡고 → 자릿수로 판정 → 자릿수대로 조립」한다.
  **번호가 없는 것보다 틀린 번호가 나쁘므로, 애매하면 버린다.** (`tests/phone-extract.test.ts`)

### 이번에 채운 것 — **코스 편집** (장소 교체 · 순서 변경)

AI 를 **다시 부르지 않는다.** 코스를 통째로 재생성하면 마음에 들어 했던 나머지 장소까지
바뀌고, 「이 한 곳만 마음에 안 든다」에 대한 답으로는 과하다. **Gemini 호출 0 이다.**

- 교체 후보는 **그 장소 주변**에서 찾는다. 출발지 기준으로 찾으면 코스 후반부를 바꿀 때
  엉뚱하게 먼 곳이 올라온다. **같은 역할**만 후보가 된다 — "카페를 바꾼다"고 눌렀는데
  국밥집이 나오면 코스 구성이 무너진다.
- 🔴 **클라이언트가 보낸 stops 배열을 그대로 저장하지 않는다.** 「무엇을 어떻게 바꿀지」만
  받고(`op: move | replace`) 조작은 서버가 한다. 통째로 받으면 아무 좌표·아무 문구나 심을 수 있다.
  교체할 때도 클라이언트가 준 contentId 를 믿지 않고 **후보를 다시 뽑아 그 안에 있는 것만** 허용한다.
- **시간 슬롯은 자리에 남고 장소만 자리를 바꾼다.** 사용자가 바꾼 건 「무엇을 가는가」지
  「언제 가는가」가 아니다. 날짜 경계는 넘지 않는다(1일차 장소가 2일차로 가면 코스가 깨진다).
- 교체된 장소의 설명·팁·hook 은 **지운다.** 다른 장소의 설명이 붙은 채 남으면 거짓말이 된다.
  방문일 영업 확인도 `unknown` 으로 되돌린다 — 확인되지 않은 것을 확인됐다고 말하지 않는다.
- 교체·이동 뒤 **이동정보와 총거리를 다시 계산**한다. 안 하면 「차로 15분」이라 적힌 채
  실제로는 40분인 코스가 된다. (`tests/course-edit.test.ts` 11건이 이걸 지킨다)

#### 🔴 권한 — 로그인이 없는데 어떻게 「내 코스」를 가르나

`share_slug` 는 **공유하라고 만든 값**이다. 그것만으로 편집을 열면 링크를 받은 누구나
남의 코스를 고칠 수 있다. 그래서 **생성 응답 1회로만 나가는 편집 토큰**(014)으로 가른다.

- 조회 API 는 이 토큰을 **절대 응답에 싣지 않는다**
- 토큰이 없거나 틀리면 **404 와 같은 얼굴**을 보여준다 — "토큰이 틀렸습니다"라고 알려주면
  어떤 slug 가 편집 가능한지가 새어나간다
- 비교는 `timingSafeEqual`. 문자열 `===` 는 응답 시간 차이로 토큰을 한 글자씩 맞춰볼 여지를 준다
- 편집한 코스는 자동으로 보존 대상이 된다 — 손을 댔다는 건 아낀다는 뜻이다

## 3. 저장 — 「전부 저장하되, 안 쓰면 사라진다」

### 무엇이 문제였나
- 생성 즉시 **무조건** 영구 저장되고 **삭제 수단이 없었다**
- 대부분의 코스는 한 번 보고 버려지는데 그게 전부 남는다
- 출발 좌표(집일 수 있다)를 포함한 기록이 무기한 남는다

### 결정
기본 **30일 만료**, **공유·저장을 누른 코스만 영구 보존**.

- 「누른 적 있으면 절대 안 지운다」가 규칙이다 — **이미 공유된 링크가 어느 날 깨지는 것이
  가장 나쁜 결과**다. `POST /api/course/[slug]/keep` 이 그 「눌렀다」이고, 카카오 공유·링크 복사
  양쪽에 걸려 있다. 멱등이며, 실패해도 200 을 준다(공유는 사용자가 원한 동작이고 보존 표시는 부수 효과다).
- 기존 행은 전부 `is_kept = true` 로 둔다. **소급 삭제하지 않는다.**
- 정리는 **코스를 새로 저장할 때 조금씩**(`sweepExpiredCourses`, 50건씩). 스케줄러를 하나 더 두면
  그게 또 관리 대상이 된다. `await` 하지 않는다 — 정리 때문에 코스 생성이 느려지면 안 된다.
  트래픽 없는 기간에도 돌리고 싶으면 마이그레이션 주석의 `pg_cron` 예시를 쓴다.

## 3-b. 로그인 — 「기기를 바꿔도 남는다」

편집 토큰은 **브라우저에만** 있다. 시크릿창을 닫거나 폰을 바꾸면 내가 만든 코스에
접근할 방법이 사라진다. 로그인은 그 소유권을 계정으로 옮기는 장치다.

- **카카오 OAuth**(Supabase Auth). 이 앱은 이미 카카오 SDK·공유를 쓰고 있고 이용자층도 맞는다
- 🔑 **claim 이 핵심이다**(`POST /api/course/[slug]/claim`). 로그인 전에 만든 코스는
  브라우저에만 증거가 있다. 로그인한 뒤 **편집 토큰으로 「이건 내 코스다」를 증명해** user_id 를 붙인다.
  이 다리가 없으면 로그인해도 그동안 만든 코스는 영영 남의 것이 된다. 코스 화면을 열 때
  자동으로 한 번 시도하고, 성공하면 다시 부르지 않는다.
- 로그인해서 만든 코스는 **만료시키지 않는다** — 「내 코스」에 남아야 하기 때문이다
- 「내 코스」 목록은 익명 SELECT 정책을 타지 않는다. 서버가 서비스롤로 user_id 를 걸러 읽는다

### 🔴 기본은 **꺼져 있다** — 그리고 그건 의도다

`NEXT_PUBLIC_AUTH_ENABLED` 가 `'true'` 가 아니면 미들웨어도, 로그인 버튼도 동작하지 않는다.
**서비스는 지금과 100% 동일하게 동작한다.**

Supabase 대시보드 설정이 끝나기 전에 켜면 로그인 버튼이 에러만 뱉는데,
**고장난 버튼은 로그인이 없는 것보다 나쁘다.**

#### 🔴 실측으로 막혔던 지점 — `KOE205` (2026-08-31)

설정을 다 마치고 실제로 로그인을 누르니 카카오가 이렇게 답했다:

> **Invalid Request (KOE205)** — Unset consent item(s): `account_email`

**원인**: Supabase 의 Kakao provider 는 `account_email` scope 를 **고정으로** 붙인다.
카카오가 안내하는 해법 중 *"미설정 동의항목을 제외하고 재요청"* 은 우리 쪽에서 불가능하다 —
`signInWithOAuth` 의 `scopes` 옵션을 실측해보니 **교체가 아니라 추가**로 동작한다:

```
요청: scopes=profile_nickname profile_image
결과: scope=account_email+profile_image+profile_nickname+profile_nickname+profile_image
```

그리고 `account_email` 동의항목은 **비즈 앱에서만** 쓸 수 있다.

**해법 (사업자등록번호 없이도 된다)**:
[앱] → [일반] → [비즈니스 정보] → **[개인 개발자 비즈 앱]** 으로 전환한다.
조건은 **앱 소유자 본인인증 + 카카오비즈니스 통합 서비스 약관 동의** 뿐이다.
전환 후 [카카오 로그인] → [동의항목] 에서 **카카오계정(이메일)을 「선택 동의」로** 켜고,
Supabase 쪽 **`Allow users without an email`** 을 켜두면 사용자가 거절해도 로그인이 성립한다.

> ⏳ **전환·검수 대기가 마감(9/21)을 위협하면** `NEXT_PUBLIC_AUTH_PROVIDER=google` 로 우회한다.
> 코드 변경 없이 환경변수만 바꾸면 된다. Google 은 운영 프로젝트에서 아직 꺼져 있으므로
> Supabase → Providers → Google 을 켜야 한다.

#### 켜려면 (박재오만 할 수 있는 일) — 2026-08-31 공식 문서로 확인

> 🔴 **「Redirect」가 두 곳에 나온다. 이걸 헷갈리는 게 이 설정에서 제일 흔한 사고다.**
> - **카카오 쪽 Redirect URI** = **Supabase** 주소. 카카오가 인가코드를 Supabase 로 보낸다
> - **Supabase 쪽 Redirect URLs** = **우리 앱** 주소. Supabase 가 사용자를 우리에게 돌려보낸다
>
> 서로 다른 값이다. 한쪽에 다른 쪽 주소를 넣으면 로그인이 안 된다.

**1. Kakao Developers ([developers.kakao.com](https://developers.kakao.com))**

> 🔴 **콘솔이 개편됐다(2026-08-31 문서 확인).** 예전 경로인 「제품 설정 → 카카오 로그인 → 보안」이
> 아니라, 키·시크릿·Redirect URI 가 **전부 `플랫폼 키` 아래**로 모였다.
> 특히 **클라이언트 시크릿은 REST API 키를 클릭해 들어가야 나온다** — 목록 화면에는 안 보인다.

| 위치 | 할 일 |
|---|---|
| 애플리케이션 추가 | 앱 이름 `이모추`, 회사명 입력 |
| 앱 설정 → 앱 → **플랫폼 키** | **REST API 키** 복사 → Supabase 의 **Client ID** |
| 〃 → **REST API 키를 클릭** → 클라이언트 시크릿 | **활성화 ON** 후 값 복사 → Supabase 의 **Client Secret** |

| 카카오 로그인 | **활성화 ON** |
| 카카오 로그인 → **동의항목** → 개인정보 | **닉네임**·**프로필 사진** 만 (이메일은 넣지 않는다) |

> 🔑 **`account_email`(카카오계정 이메일)은 요구하지 말 것.** 그 동의항목은 **비즈앱 전환**이

> `user.id` 만 본다. 대신 Supabase Kakao 설정에서 **`Allow users without an email` 을 켜면**
> 비즈앱 전환 없이 끝난다.

## 4. 공유

- **B코스(이색 발견)는 이제 눌러야 만들어진다.** 예전엔 요청마다 A/B 를 같이 만들어 비용이
  정확히 2배였는데, B 를 보는 사람은 일부다. 탭 자체가 「이색 발견 만들기」 진입점이 됐다.
  - 🔑 조건을 클라이언트에서 받지 않고 **DB(`request_params`)에서 읽는다** — 공유 링크로 들어온
    사람은 위저드를 거치지 않아 조건을 갖고 있지 않다.
  - 이미 만들어 둔 B 가 있으면 그대로 준다. **같은 코스에 두 번 과금하지 않는다.**
- **코스별 공유 카드 이미지**(`app/(pages)/course/[slug]/opengraph-image.tsx`).
  예전엔 첫 장소의 TourAPI 사진 한 장을 썼는데, **사진 한 장으로는 「코스」가 안 보인다.**
  지금은 제목 + 동선(장소 → 장소 → 장소) + 장소 수 · 총거리 + 출처 표기를 그린다.
  - 🔴 `generateMetadata` 에서 `openGraph.images` 를 지정하면 이 파일을 **덮어쓴다.** 그래서 뺐다.

## 6. 계측

`[이모추AI:usage]` 로그를 심었다(prod 포함). `model` · `variant` · `in` · `out` · `total` 이 남는다.
**비용은 재야 관리된다** — 이게 없으면 다음 과금 판단이 또 추정이 된다.

`total > in + out` 이면 그 차이가 thinking 토큰이다. `thinkingBudget` 적용 후엔 `total = in + out` 이다.
