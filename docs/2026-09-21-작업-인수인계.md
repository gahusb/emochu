**착수 순서**
1. 먼저 **측정부터 한다.** 지금은 "느리다"만 알지 **어디가 느린지 모른다.** `app/api/course/route.ts` 의 단계별(후보 수집 → 상세 보강 → 스코어링 → Gemini → 검증) 소요를 로그로 찍어 3~5회 표본을 잡아라.
2. 측정 결과에 따라 갈린다:
   - Gemini 응답이 지배적이면 → **응답을 빠르게 하는 것보다 진행 상태를 보여주는 쪽**이 비용 대비 효과가 크다. 엔진이 이미 그 순서로 도니 단계만 흘려보내면 된다.
   - 상세 보강(`detailIntro2` 등) 호출이 지배적이면 → 이미 `docs/2026-09-10-상세조회-한도-운영시간-보완.md` 에서 중복 합치기·동시성 제한을 넣었으니 **그 문서부터 읽어라.** 같은 일을 다시 하지 마라.

**하지 말 것**: 체감 개선한답시고 TourAPI 응답을 캐시로 때우는 것. 심사가 **인증키로 개발 기간 내 호출건수를 검증**한다(`CLAUDE.md`). 실호출 이력이 안 남으면 손해다.

**검증**: 단계 표시가 붙었다면 `npm test` + 실제 배포본에서 한 번 생성해 보고 문구가 순서대로 바뀌는지 눈으로 확인.

### 🔴 P2 — 홈 카드 배지 「공연」 오표기 (원인 확정됨) — ✅ 처리(배포·육안 확인 남음)

**원인** (오늘 코드로 확인)
- `app/components/SpotCard.tsx:31` — `A0206: { label: '공연', ... }`
- `lib/tour-api.ts:430` — 같은 코드를 `{ label: '공연장', cat2: 'A0206' }`

**고칠 것**
1. `app/components/SpotCard.tsx:31` 의 `A0206` 라벨을 **「문화시설」** 로.
2. 진짜 공연은 소분류(`A02060500` 계열)나 `contentTypeId=15`(행사/공연/축제)로 구분.

**왜 급한가**: 첫 화면에서 바로 보이고, **데이터 활용 배점(1차 20점)** 의 정확도 인상에 직결된다.

재현한 시나리오(결과가 안정적이었다):
```
/course → 위치 배너 닫기("서울로 볼게요") → 도시 선택 → 서울
       → 힐링이 필요해요 → 다음

       → 하루(6~8시간) → 가족+아이 → 다음
```

⚠️ **함정**: 「코스 만들기」는 **상단 네비게이션 링크와 텍스트가 같다.** 텍스트로 요소를 찾으면 네비를 먼저 집어서 아무 일도 안 일어난다. 버튼을 정확히 지정해라.

생성 결과 예: `/course/bb5ta6j7`, `/course/94h5xdrw`
