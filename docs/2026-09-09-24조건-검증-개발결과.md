## 2. 검증기 개선

### 예비 실측(v1)과 본 측정(v2)을 분리

기존 도구는 묶음 전체의 AI 요청을 3회로 제한했다. 앞 조건의 재시도가 예산을 소진하여 뒤 조건이 AI 호출 없이 규칙 대체되는 편향을 발견했다. v1 결과는 예비 실측으로 보존한다.

v2는 **조건당 첫 AI 시도 1회, 묶음 전체 최대 3회**다. 첫 시도가 실패하면 후속 AI 요청을 차단하고 규칙 대체 결과를 기록한다. 모든 조건에 첫 시도 기회를 주기 위한 진단 정책이며 **운영 서비스의 모델 재시도·폴백 전체 성공률을 측정하지 않는다**. 운영 생성 엔진의 재시도 정책은 바꾸지 않았다.

- 한 묶음은 3조건, 전체 외부 요청 최대 240회. 개인·DB 데이터 경로는 네트워크 허용 목록에서 차단한다.
- 한 조건이 실패해도 결과를 `failed`로 남긴다. 부족한 후보를 창작해 채우지 않는다.
- `course-audit.ts`: 원본 ID·제목·좌표, 방문일·휴무, 시간 겹침·예산·식사, 운영시간 불일치/미확인, 접근성 원문 정보의 분모, 날짜별 예보 미확인을 나눠 기록한다.
- `matrix-summary.mjs`: 명시한 보고서만 집계하고 중복 묶음·다른 날짜·v1/v2 혼합·신규/재생/규칙 전용 혼합은 거부한다. 누락된 조건을 성공으로 채우지 않는다.
- `knownChecksPass`는 **검사 가능한 조건의 통과**일 뿐이다. 영업시간 미확인이나 예약·실제 교통까지 확인했다는 뜻이 아니다.
- 후보에 특정 역할이 전혀 없으면 구성 검사의 요구가 완화될 수 있다. 후보 역할과 실제 방문 개수를 함께 기록하며, 구성 통과만으로 모든 편의 조건이 충족됐다고 주장하지 않는다.

실행 예:

```sh
node scripts/verify-live-course.mjs --matrix 1
node scripts/verify-live-course.mjs --matrix 8 --rules
node scripts/summarize-course-matrix.mjs report-파일1.json report-파일2.json
```

유료 호출은 명시적 실측 실행에만 발생한다. `--rules`는 AI를 전혀 호출하지 않지만 관광·날씨 API는 사용한다. 일반 단위 테스트·release-green은 외부 AI를 호출하지 않는다. 집계 명령은 로컬 파일만 읽는다. **현재 두 서비스의 429를 확인했으므로 위 외부 호출 명령을 반복 실행하지 않는다.** 자동 재시도나 예약 실행도 등록하지 않았다.

## 3. 실측에서 발견한 문제

### AI 응답 지연·503·429와 상세정보 한도

본 측정 15번의 첫 AI 요청은 HTTP 200 3회, 25초 제한의 AbortError 6회, 503 1회, 429 5회였다. 묶음 4의 429를 확인할 때 묶음 5가 이미 진행 중이었고, 그 뒤 묶음 6~8은 AI를 차단했다. 첫 429 직후 모든 요청이 즉시 중단됐다고 소급해 기록하지 않는다.

후속 도구에는 같은 묶음에서 Gemini 429를 관측하면 남은 AI 요청을 차단하는 가드를 추가했다. 단위 테스트로 검사했으며 이를 확인하려고 다시 유료 호출하지 않았다. 운영 엔진의 재시도 정책이나 다른 실행 프로세스까지 제어하는 전역 회로 차단기는 아니다.

규칙 전용 묶음에서도 `KorService2/detailIntro2`가 429 126회와 시간 초과 1회를 반환했다. 재생 시에도 상세 조회가 실패했다. 후보 목록은 얻었지만 영업시간 정보가 크게 줄어든 상태다. 추가 외부 검사는 중단했으며, 429의 정확한 한도 종류·해제 시각·계정 잔량은 확인하지 않았다. 규칙 대체 결과를 AI 성공으로 세거나 미확인 시간을 정상 운영으로 보정하지 않는다.

### 반나절 시간 예산 초과

예비 서울 일정은 10시 전시(80분) → 11:30 식사(60분) → 12:40 카페(50분) → 13:40 경희궁공원(80분)으로 15시에 끝났다. 식사와 이동 겹침은 없지만 반나절 예산 4시간을 1시간 초과했다.

`course-budget.ts`는 시간 예산 초과 시 다음 두 단계를 순서대로 시도한다. **체류시간을 줄이지 않으며, 검사에 통과하는 시도만 한 번에 반영한다.**

1. 이동 추정 뒤의 대기 간격을 줄여 같은 장소를 더 이른 시각에 방문한다. 첫 방문·축제·숙박·일차 경계를 보존하고, 기존 점심/저녁 구간을 지킨다. 확인된 운영시간·준비시간·입장/주문 마감 안에서만 이동한다. 운영시간을 모르면 계속 미확인으로 남긴다.
2. 간격 조정으로 해결되지 않으면 그 시도를 버리고, 원래 일정의 **끝 선택 관광/문화 한 곳을 제외**할 수 있는지 검사한다.

두 번째 단계의 제한은 다음과 같다.

- 반나절 3곳·하루 5곳·여유롭게 4곳의 최소 개수 유지.
- 다른 볼거리나 축제가 남고 식사·카페 균형 보존.
- 남은 일정의 시간 겹침·예산·20km 초과 구간 검사 통과.
- 축제·숙소·식사·카페·레포츠는 이 단계에서 제거하지 않음. 1박2일에 단일 하루 예산을 적용하지 않음.

결과에는 ‘대기 간격 보완’ 또는 ‘시간 예산 보완’과 제외한 장소를 표시한다. 이전 시각을 설명하던 문구·전체 요약·비용 추정은 변경에 맞춰 비우거나 다시 만든다. 해결되지 않는 일정은 경고로 남긴다. 전면적인 동선 최적화나 모든 시간표의 자동 수정을 의미하지 않는다.
