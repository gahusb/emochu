## 1. 결론과 제품 방향

**“취향과 동행 조건에 맞춰, 실제 관광정보로 이번 주말 동선을 만들고 바로 수정·방문할 수 있는 AI 여행 플래너”**를 주제로 고정한다. 사주(오행)는 선택을 즐겁게 만드는 선택형 테마다. 정밀 사주·예언·과학적 적합도라고 주장하지 않는다. 입력도 출생연도 기반 오행만 사용하며, 기분은 사용자가 직접 고른 값을 보존한다.

기능 수보다 생성한 코스가 실제로 성립하는지, 데이터가 어떤 결정에 쓰였는지, 모바일에서 끝까지 사용할 수 있는지가 우선이다. 수상 확률이나 예상 심사 점수는 현재 자료로 산정할 수 없다.

## 2. 현재 구성

- Next.js App Router / React / Tailwind: 홈 → 4단계 위저드 → 생성 대기 → 일정·지도 → 장소 교체·순서 변경 → 저장·공유·커뮤니티.
- `app/api/course/route.ts`: 입력 검증, 사용량 제한, 관광 후보/날씨/축제/숙박 수집, 상위 후보 상세·무장애 보강, 생성, 저장.
- `lib/weekend-ai.ts`: 취향35·동행20·날씨15·거리20·계절10에 편의시설·기분 보정. 오행은 최대5점의 약한 가산점. 역할별 후보 배분 후 Gemini가 JSON 코스 작성. 장애 시 규칙 기반 대체.
- Supabase: 코스 JSON·원본 조건·편집 토큰·기간/공개 여부 저장. 생성자만 편집 가능. B 코스는 누를 때 생성하여 기본 요청 비용을 줄임.
- 이미 구현된 장점: 후보 기반 생성, 구조화 출력, 휴무 파싱, 접근성 원문 보존, 카페/식당 분류 분리, 4단계 입력 복원, 장소 교체, 공개 동의 기반 커뮤니티. 전면 재작성하지 않는다.

## 4. 프롬프트 수정 원칙

우선순위는 **데이터 사실성·방문 가능 날짜 → 사용자 조건 → 식사/휴식 균형 → 약한 오행 테마 → 감성 문구**다. 후보 설명은 외부 데이터이므로 안에 섞인 명령을 따르지 않도록 한다. 근거 없는 개화 절정, 할인, 대기시간, 추천 메뉴, 무장애 보장을 금지한다. 사주로 사용자가 고른 기분이나 접근성 조건을 덮어쓰지 않는다.

구조화 출력은 JSON 모양만 제한한다. ID, 원본 좌표, 중복, 날짜, 휴무, 시간 형식은 서버에서 별도로 검증한다. 구성 재시도는 기존 opt-in 정책을 유지하여 비용·지연을 무조건 늘리지 않는다. 모델 교체·SDK 전체 이관은 제출 직전 안정성을 위해 별도 실측 후 결정한다. 기존 주석의 모델 가격·벤치마크는 이번 검토에서 재측정한 수치가 아니다.

## 5. 관광 API 활용을 심사 증거로 바꾸기

현재 구현은 관광공사 **2개 서비스 제품(KorService2 / KorWithService2)**의 총 12개 오퍼레이션이다. 이를 ‘12개 API 상품 연동’으로 부풀리지 않는다. 아래는 코드 연결 기준이며 실호출 성공 증명은 별도 수집한다.

| 데이터 / 오퍼레이션 | 사용자 결정에 쓰는 방법 | 제출 증거 |
|---|---|---|
| locationBasedList2, areaBasedList2 | 여행 중심지 인근의 실재 장소 후보·역할 확보 | 동일 조건의 후보와 최종 ID 대조 |
| searchKeyword2, areaCode2, categoryCode2 | 지역/카테고리 탐색 및 장소 검색 | 탐색 화면 → 상세 화면 흐름 |
| searchFestival2 | 여행 날짜에 개최하는 축제만 후보 편입 | 종료 축제 제외, 일요일만 열리는 행사 사례 |
| searchStay2 | 1박2일 숙박 후보 (예약 가능 보장 아님) | 숙박 포함 2일 일정과 예약 확인 안내 |
| detailCommon2, detailIntro2 | 소개·연락처·운영/휴무·시설 | 원문, 코스 배지, 휴무 교체 전후 |
| detailImage2, detailInfo2 | 상세 이미지·추가 이용 정보 | 상세 패널과 출처 표시 |
| detailWithTour2 | 보행/시각/청각/영유아 정보 보강 | ‘데이터 있음’과 ‘미확인’ 비교, 원문 노출 |
| 기상청 예보 + Kakao 지도 | 방문일 날씨로 우선순위 조정, 위치 확인·길찾기 연결 | 우천/조회 실패, 모바일 지도·길찾기 |

API 추가는 목표가 아니라 수단이다. 남은 기간에는 무장애·기간·운영정보의 활용 깊이를 증명한다. 전국 서비스는 유지하고, 비서울 한 지역을 **검증용 시범 시나리오**로 집중 테스트하되 지역특화 가점을 자동 충족한다고 주장하지 않는다.

## 8. 이번 작업의 구현·검증 기록

### 반영 완료

1. `trip-context.ts` — KST 여행 날짜와 오행을 통일. 서버가 자유 문구 대신 여행일 테마를 재계산한다. 위저드의 방문일 변경도 미리보기에 반영한다.
2. `weekend-ai.ts` — 프롬프트 사실성 우선, 단일 방문일 날씨·무장애 원문·축제 시작/종료일 전달. 후보 밖 ID 거부, 명칭·좌표·이미지·타입·시설을 원본으로 복구. 시간 형식/일차 검증, 중복 제거 후 거리 계산. 비활동 조건의 후보 보충에서 레포츠가 재유입되는 버그 수정.
3. `course-quality.ts` — AI·규칙 기반 결과 모두 일차별 축제·휴무 검증. 같은 역할의 후보로 교체하고 불가능하면 제외. 이동·체류 겹침, 시간 예산, 부족한 구성은 경고로 제공한다. 실제 오행 매칭 규칙에 맞는 장소에만 테마 배지를 붙인다.
4. `generateFallbackCourse` — 1박2일을 이틀로 분리하고 실제 숙박 후보를 넣는다. 후보가 없으면 숙소 별도 예약 안내. AI 성공/규칙 기반 대체를 결과에 구분한다.
5. `app/api/course` — 잘못된 입력·캐시된 B 조회는 일일 생성량에서 제외. 도시 중심 주변 후보 우선. 전체 요청에서 남은 예산으로 AI 요청 취소, 실패 후 재시도 시 첫 유효 코스 보존. 추가 운세 문구용 AI 호출 제거. DB 오류 필드 확인, 임시 결과 상태와 일반화된 오류 메시지 반환.
6. `weather-api.ts` / `tour-api.ts` — 외부 요청별 시간 제한, KST 발표시각 및 주말 계산. API 응답이 있더라도 주말 예보가 없으면 맑음으로 해석하지 않는다.
7. 결과 화면 — 여행 날짜·원본 대조 수·확인 필요 사항 표시. ‘영업 확인’을 ‘정기휴무 아님’으로 정정. 거리·이동시간은 직선 추정임을 표시. 사주 카드에 재미용 테마·약한 반영 원칙 명시.
8. 반응형 — 모바일 일정/지도 전환을 타임라인 상단으로 이동. 장소 행동 버튼 줄바꿈·44px 조작, 긴 제목 줄바꿈. 지도 연결 실패 안내와 외부 길찾기. 사진 로딩 실패 시 빈 이미지 영역 제거.
9. 브라우저 상태 — 저장소 차단 시 메모리 결과 유지, 편집 후 캐시 갱신, 다른 슬러그에 이전 상태가 남지 않게 분리. 서버 저장 실패 시 공유·편집·B 생성 숨김. 공유 주소를 절대 URL로 복사하며 권한 거절 시 수동 복사 제공.
10. 실제 UI 테스트에서 발견한 결함 — 위치 권한 안내가 위저드 ‘다음’ 버튼을 가리는 문제를 재현하고 홈에서만 표시하도록 수정. 교체 창의 Tab 순환·Esc·포커스 복귀, 화면 확대 제한 해제.
