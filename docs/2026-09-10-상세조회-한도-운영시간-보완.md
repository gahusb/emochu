# 상세 조회 한도 대응과 운영시간 미확인 표시

2026-09-10 KST 로컬 개발 기록. [이전 24조건 검증](2026-09-09-24조건-검증-개발결과.md)에서 확인한 관광 상세정보 429와 높은 운영시간 미확인 비율에 대응했다. **이번 후속 개발은 외부 관광·날씨·AI 호출 없이** 고정 응답과 모의 화면으로 검사했다. 날짜가 바뀌었다는 이유로 계정 한도가 해제됐다고 가정하지 않았다. 배포·운영 DB 변경·제출은 하지 않았다.

## 1. 수정 결과

### 관광 소개 상세 요청 보호

`detailIntro2`를 사용하는 후보 보강·축제 시간·장소 교체·장소 상세 조회가 같은 프로세스의 보호 장치를 공유한다.

| 항목 | 이전 | 수정 |
|---|---|---|
| 같은 ID·유형 동시 요청 | 별도 요청, 실행 중 요청 합치기 없음 | 하나의 요청을 공유하고 각 호출자에게 별도 객체 반환 |
| 동시 상세 요청 | 후보 보강 20개가 동시에 시작 | 한 프로세스 최대 4개, 나머지 대기 |
| 정상 응답 | Next의 기존 60초 재검증 설정 | 기존 설정 유지 + 프로세스 내부 60초, 최대 128건 |
| 429 이후 대기 요청 | 이미 병렬 실행되거나 다음 호출에서 다시 시도 | 아직 시작하지 않은 상세 요청 억제, 실패 상태 유지 |
| 대기 시간 | 별도 상한 없음 | 대기+네트워크 7초 예산. 만료한 대기 요청은 전송하지 않음 |
| 메모리 경계 | 별도 없음 | 실행·대기 중 고유 요청 최대 256개 |

429의 `Retry-After` 초 또는 날짜를 받아 최소 60초·최대 24시간 억제한다. 없거나 해석할 수 없으면 60초다. **억제 시간이 지나도 자동 재시도하지 않고 다음 명시적 호출 때만 검사**한다. 이미 전송한 최대 4개의 응답을 되돌릴 수는 없다. 유효한 정상 캐시는 제한 중에도 제공하지만, 만료한 응답이나 실패를 정상 빈 목록으로 제공하지 않는다.

인증키가 바뀌면 캐시·제한 상태도 분리한다. 기존 대기 요청은 처음 요청할 때의 인증키를 유지한다. 키·기관 오류 원문·전체 요청 URL을 새 제한 오류 메시지에 넣지 않는다.

범위와 한계:

- 보호 대상은 `KorService2/detailIntro2`다. 관광 목록·이미지·무장애 정보·Gemini를 모두 제어하는 공통 제한기가 아니다.
- 메모리는 프로세스 내부다. 서버리스 인스턴스 간 공유, 재시작 후 유지, 계정 전체 사용량 관리가 아니다.
- 기관 오류 코드가 붙은 HTTP 200은 계속 실패로 처리하지만, 코드별 한도를 추측하여 429와 동일시하지 않는다.
- 7초 예산은 일부 정보가 미확인으로 남는 것을 허용해 생성 흐름을 보호한다. 동시 실행 제한으로 모든 20개 후보의 상세정보를 확보한다는 보장은 없다.
- 캐시 도입으로 실제 운영 요청이나 비용이 얼마나 감소했는지는 아직 실측하지 않았다. 캐시 설정을 공모전 규정 준수나 가점의 근거로 제시하지 않는다.

## 2. 정기휴무와 운영시간을 분리

기존 `openStatus`는 정기 휴무 요일만 대조했는데 일부 화면은 이를 ‘운영시간 확인 필요’라고 표현했다. 정기휴무가 아니어도 오후에만 여는 장소일 수 있으므로 두 축을 분리했다.

| 정보 | 표시와 의미 |
|---|---|
| 정기 휴무 요일 확인 | ‘정기휴무 아님’ / ‘정기휴무 미확인’ |
| 제안 시각·체류와 원문 운영구간 | `hoursStatus`: `within` / `outside` / `unknown` |
| 결과 요약 | 전체 방문 지점 중 원문 운영구간 일치·미확인·불일치 개수 |
| 개별 장소 | ‘제안 시간은 원문 운영구간 내’ / ‘제안 시간과 운영시간 불일치’ / ‘운영시간 미확인’ |

영업시간·준비시간·입장/주문 마감과 체류 전체를 대조한다. 축제는 명시된 행사시간과 방문 날짜를 사용한다. 원문이 없거나 복합 조건을 파싱하지 못하면 미확인이다. 숙박은 관람 운영시간이 아니라 체크인·숙박 조건이 필요하므로 이 검사에서 미확인으로 남긴다. **원문 구간 일치는 실제 운영·휴무 예외·예약 가능 보장이 아니다.**

생성 단계는 AI가 쓴 확인 상태를 버리고 서버가 원본으로 다시 계산한다. 장소 교체와 순서 편집으로 시각·체류가 바뀌면 이전 일치 상태를 미확인으로 되돌린다. 기존 저장 코스에 새 필드가 없으면 미확인으로 세며 소급해 확인 완료로 표시하지 않는다. 새 DB 마이그레이션은 필요 없는 선택 필드다.

## 4. 제출 전략과 다음 작업

제출 자료는 **공공데이터의 활용 경로와 정보 신뢰도**를 강조한다. ‘API를 많이 호출한다’보다 ‘여행일·시각·체류 조건과 원문을 대조하고, 확인할 수 없으면 그 한계를 보여준다’가 이번 개발의 근거다. 오행 테마는 여전히 선택형 보조 조건이며 이 단계에서 영향력을 확대하지 않았다.

1. 한도 상태를 확인한 뒤 최소 표본부터 재실측한다. 9/9의 AI 미시도 9조건·운영시간 부족 95/127은 이번 모의 검사로 해소된 것이 아니다. API 계정의 실제 잔량·해제 시각은 미확인이다.
2. AI 25초 지연·503·429와 운영 재시도 전체를 별도 점검한다. 이번 수정은 Gemini 모델·프롬프트·과금 정책을 바꾸지 않았다.
3. 실제 폰의 정상 지도·길찾기·저장·공유, 공식 기능설명서 이관·실제 배포 화면·90초 시연을 준비한다. 외부 배포나 운영 계정 변경은 별도 실행 단계다.
