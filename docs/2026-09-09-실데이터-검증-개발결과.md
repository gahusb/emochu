## 2. 실측 범위와 재현

`node scripts/verify-live-course.mjs`

- `lib/course-candidates.ts`로 기존 수집 코드를 옮겨 실제 생성 API와 측정기가 같은 함수를 사용한다. 데이터 수집 → 상세 보강 → 점수화 → 선택적 무장애 조회 → AI → 최종 검증을 수행한다.
- 코스 생성 HTTP 엔드포인트는 호출하지 않는다. 따라서 코스 저장, 조회수, 일일 사용량, 만료 코스 삭제를 실행하지 않는다. 저장·공유·인증의 운영 연동은 이 측정의 범위 밖이다.
- 측정기의 네트워크 대상은 관광·날씨·Gemini 호스트로 제한한다. DB 및 임의 호스트를 차단한다. API 키는 프로세스 내부에서만 로드하고 출력·파일은 원문/인코딩 변형을 마스킹한다.
- 첫 실행 상한은 AI 6회였고 실제 3회 전송했다. 두 번째 실행은 상한을 3회로 내려 실제 3회 전송했다. 현재 스크립트의 상한은 **실행 전체에서 3회**다. 재시도도 상한에 포함한다.
- 원본 보고서는 git 제외된 `.scratch-live-course/`에 보관한다. `report-2026-09-08T23-00-05-157Z.json`(KST 08:00), `report-2026-09-08T23-07-34-255Z.json`(KST 08:07). 파일명의 날짜는 UTC이다.
- PASS는 결과 존재·최종 장소 원본 대조 검사를 뜻한다. **일정 품질 경고가 0건이라는 뜻이 아니다.**

## 3. 수정 전후 표본

시간은 로컬에서 수집·보강·생성·최종 검증까지 잰 값이다. 배포 서버의 응답시간이나 P95가 아니다.

| 조건 | 수정 전 | 수정 후 | 해석 |
|---|---|---|---|
| 서울 / 토요일 / 반나절 / 혼자 | AI, 3곳, 9.25초 | AI, 3곳, 9.07초 | 토요일 예보 유지, 선택하지 않은 일요일의 미확인 경고를 붙이지 않음 |
| 강릉 / 일요일 / 하루 / 가족·이동약자 정보 | AI, 6곳, 12.59초 | AI, 5곳, 17.61초 | 503 후 1회 재시도. 일요일 예보 미확인·저녁 식사 누락을 정확히 경고 |
| 안동 / 1박2일 / 연인 | AI, 9곳, 18.61초 | 규칙, 9곳, 1.37초 | 앞선 재시도로 실측 상한 소진. 수정 후 AI 비교 표본으로 사용할 수 없음 |

- 최종 결과의 장소 원본 대조: 수정 전 18/18, 수정 후 17/17. 최종 목록 밖 ID 0건. 장소 설명·영업시간·실제 방문 가능성 전체가 무오류라는 의미는 아니다.
- `gemini-3.6-flash`의 6회 전송 중 HTTP 200은 5회, 503은 1회였다. 503은 재시도 후 복구했다. 모델 목록 조회에서도 현재 구성된 모델이 확인돼 모델 교체는 하지 않았다.
- 응답에 토큰 사용량이 기록된 5건 합계: 입력 18,106 / 출력 8,925 / 총 27,031토큰. 503 응답은 usage 없음. **청구 금액은 검증하지 않았다.**
- 안동 수정 후 규칙 결과에 20km 초과 구간이 남았다. 동선이 최적화됐다고 주장하지 않는다.

## 4. 관광 데이터가 실제 결정에 쓰인 지점

서비스 소스는 관광 API 상품 **2종·오퍼레이션 12개**를 사용한다. 이번 코스 표본에서 실호출한 것은 그중 **5개 오퍼레이션**이다. 나머지 장소 상세·검색·코드 조회까지 모두 실검증했다고 쓰지 않는다.

| 실제 오퍼레이션 | 전후 합계 호출 | 활용·검증 결과 |
|---|---:|---|
| KorService2 / locationBasedList2 | 26 | 도시 주변 후보 및 숙박 수집. 일반 후보 서울 80·강릉 74·안동 70개 |
| KorService2 / detailIntro2 | 120 | 회당 상위 20개 상세 보강. 휴무·운영시간·시설 추출 |
| KorService2 / searchFestival2 | 6 | 방문일·거리 필터. 이번 3지역의 최종 축제 후보는 모두 0개여서 축제 포함 성공은 미검증 |
| KorService2 / searchStay2 | 2 | 안동 1박2일 숙박 보완, 최종 숙박 포함 |
| KorWithService2 / detailWithTour2 | 20 | 강릉에만 조건부 조회. 정보 보유 후보 8/10 → 9/10. 후보 구성이 달라졌으므로 개선률로 비교하지 않음 |

위 174회는 HTTP 200 / resultCode 0000이었다. 기상청 6회도 HTTP 200 / resultCode 00. **조회 정상과 데이터 존재·완전성은 별개**다. 수정 후 강릉의 선택 장소는 접근성 정보 4/5곳 확인, 나머지는 미확인으로 표시했다. 원문이 있다는 뜻이지 휠체어 이용을 보장하는 판정은 아니다.

별도 `tourapi-watch` 11개 점검은 제한된 실행 환경에서 전부 HTTP 이전 `EACCES`로 실패했다. 원본 실패 보고서는 보존한다. 권한을 확보한 코스 실측은 성공했지만 `areaCode2`·`categoryCode2`는 이 실측에 포함하지 않아 **현재 상태 미확인**으로 남긴다. 호출 이력을 늘리기 위한 반복 실행은 하지 않는다.

## 5. 수정한 결함

### 날짜별 날씨 범위

실제 응답은 907행이었다. 토요일은 낮 예보까지 있었지만 일요일은 **00시만** 있었다. 이전 코드는 일요일 SKY·POP·PTY가 한 건씩 있으면 충분하다고 판단하고, 12시 SKY가 없으면 맑음으로 기본 설정했다. 그 결과 일요일 최저·최고가 같고 실제로 확인하지 못한 낮 날씨를 맑다고 표시했다.

이제 09·12·18시의 SKY·POP·PTY·TMP를 확인하고 필수 값이 부족하거나 잘못됐으면 그 날짜만 미확인 처리한다. 정상 토요일은 유지한다. 홈 문장, 후보 점수, AI 프롬프트, 결과 경고가 같은 날짜별 상태를 사용한다. 조회 행 상한도 여유를 뒀지만 **이번 문제는 행 수 제한이 아니라 예보 범위 부족**이었다. 중기예보는 아직 연결하지 않았다.

### 숙박과 이동시간

1일차 20시부터 600분 숙박은 다음 날 06시까지다. 이전 검증이 이를 24시 초과로 경고했다. 이제 1박2일의 1일차 숙박만 날짜를 넘는 체류로 인정한다. 반대로 숙박 종료 전 2일차 일정은 실제 겹침으로 잡는다.

이동시간을 포함해 겹친 방문 시각은 같은 날짜 안에서 뒤로 조정한다. 장소·체류시간·방문일을 임의로 바꾸지 않으며, 조정 사실을 알리고 과거 시각에 의존하는 설명·스토리를 제거한다. 날짜를 넘기거나 시간 예산을 초과하면 경고를 남긴다. **도로 경로·교통·운영시간 자동 최적화는 아니다.**

### 식사·원본 필드

- 1박2일의 1일차 점심·저녁과 2일차 점심을 따로 검증한다. 관광지로 분류된 찜닭골목을 식당으로 간주하지 않는다. 같은 규칙을 프롬프트에도 추가했다.
- 문화시설의 `usetimeculture`, 레포츠의 시간·휴무 필드를 읽고 비어 있는 공통 필드는 다음 필드로 넘어간다. 이용요금인 `usetimefestival`은 운영시간 후보에서 제거했다.
- `강릉시립미술관 교동`의 운영시간은 수정 후 결과에서 10:00~18:00으로 보강됐다.
- 옛 날씨 데이터에서 강수형태 필드가 없어도 비로 오인하지 않도록 회귀를 수정했다.

## 6. 사주·오행을 제출서에서 설명하는 범위

같은 입력에서 오행 점수만 뺀 순위와 비교했다. 수정 후 순위가 바뀐 위치 수는 서울 0/5, 강릉 2/10, 안동 4/15였다. 이는 **가중치가 일부 후보의 순위에 영향을 주었다**는 근거이지 만족도·방문률 상승의 증거가 아니다. 실제 선택 장소의 테마 일치도 모든 코스에서 보장하지 않는다.

제출 표현: “사용자가 고른 기분·취향·현실적인 여행 조건을 우선하고, 선택형 오행 테마가 비슷한 후보의 순위와 설명 분위기에 작은 영향을 준다.” 정밀 사주풀이·운세 적중·건강 효능·재방문율 상승은 주장하지 않는다.
