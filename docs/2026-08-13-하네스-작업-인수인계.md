## ⚠️ 되풀이하지 말 것 (실제로 겪은 것)

1. **PostToolUse 훅은 `CLAUDE_FILE_PATH` 같은 환경변수를 받지 않는다.** **stdin JSON**의 `tool_input.file_path`다. 초판이 이걸 틀려 훅이 **영구 무동작**이었다.
2. **`--max-warnings 0`을 훅에 쓰지 않는다.** 이 레포엔 기존 경고 12건/7파일이 있고 `eslint.config.mjs`가 `react-hooks/set-state-in-effect`를 *의도적으로* warn으로 낮춰 뒀다. 훅이 그걸 뒤엎으면 매 편집마다 시끄러워진다.
3. **`NEXT_PUBLIC_*`는 비밀이 아니다**(이 레포에 9건). 유출 대조에 넣으면 RED 경로에서 **진짜 빌드 오류의 진단문을 오탐 마스킹**한다.
4. **출처 표기 검사는 세 번 뚫렸다** — 주석 매치 → 블록주석이 줄번호 붕괴 → 여는 `/*` off-by-one → **정규식 리터럴이 파서를 문자열 상태에 가둠**(`app/api/spot/route.ts:180`의 `/href="([^"]+)"/`). 지금은 **파서가 `code` 상태로 끝나지 못한 파일을 신뢰하지 않는다.** 이 검사기를 손볼 땐 이 네 경로를 전부 다시 확인할 것.
5. **테스트 개수를 판정에 넣어야 한다.** 안 넣으면 61→10으로 줄어도 ✅ GREEN + exit 0이 나온다.
6. **"scrub이 돌았다"와 "비밀이 없다"는 다른 주장이다.** 체크리스트에 하드코딩하지 말고 실제 값과 대조할 것.
7. 🔴 **키 유출 스캔 대상을 `loops/` 전체로 잡지 말 것.** `grep -r "serviceKey=" loops/` 는 `gate.mjs` 의 **마스킹 정규식**(`/serviceKey=[^&\s"']+/`)을 매번 잡아 **항상 유출로 오판**한다. 검사할 것은 스크립트가 **만들어낸 산출물**이지 스크립트 자신이 아니다 — `loops/*/outputs/` 와 `loops/*/PROGRESS.md` 로 한정하고, 마스킹 흔적은 `serviceKey=[^<]` 로 제외한다. (구 `verifier.md` 에 이 결함이 있었고, 2026-08-13 범용화 때 그대로 옮겼다가 첫 실행에서 잡았다.)
8. **리포트 표에서 `totalCount` 를 뽑을 때 컬럼 번호를 확인할 것.** 열 순서가 `오퍼레이션│판정│HTTP│resultCode│항목│totalCount│응답(ms)│비고` 라 `awk -F'|'` 기준 **`$7` 이 totalCount**, `$8` 은 응답 시간이다. 한 칸 밀려 읽으면 응답 시간 변동을 보고 "급변 없음"을 판정하게 된다.
9. **`text-ink-4` 를 읽혀야 하는 문구에 쓰지 말 것.** #A8917A 는 배경(#FAF7F2) 대비 **2.8:1** 로 WCAG AA(4.5:1) 미달이다. 규정상 심사자가 읽어야 하는 출처 표기 같은 건 `ink-3`(#7A6E62, 4.6:1) 이상을 쓴다.
10. **하단 고정 요소가 있는 레이아웃에 푸터를 붙일 때**, 하단 패딩을 `<main>` 에 남겨두면 안 된다. 패딩이 main 안쪽에 있으면 그 **뒤에 오는 푸터**는 여전히 탭바에 가린다 — 패딩을 마지막 요소로 옮긴다.
