# 9/9 후속 개발 — 축제 누락·조회 실패 구분

> 이 문서는 당시 350개 테스트·신규 AI 실측 기록이다. 후속 [공연·식사 충돌 보완 결과](2026-09-09-공연-식사-충돌-보완결과.md)에서 서울 저녁 누락을 해소했고 385개 테스트가 통과했다. 아래 당시 미해결 기록은 비교를 위해 보존한다.

기준: 2026-09-09 KST, 로컬 개발 버전. [식사·동선 보완](2026-09-09-식사-동선-보완-결과.md)에 이어 축제 포함 표본을 검사했다. 배포·DB 변경·접수는 하지 않았다.

## 1. 실제 원인

관광공사 행사 API의 날짜 조건 3회, 지역 조건 3회, 총 6회 GET으로 비교했다.

| 검색 조건 | 전체 / 수신 건수 | 9/12~13과 기간이 겹친 행사 |
|---|---:|---:|
| 30일 전~이번 주말, 전국 | 152 / 152 | 83 |
| 30일 전부터, 종료 조건 생략, 전국 | 327 / 327 | 83 |
| 연초부터, 종료 조건 생략, 전국 | 681 / 681 | 83 |
| 이번 주말만, 전국 | 83 / 83 | 83 |
| 이번 주말만, 기존 서울 지역코드 1 | 0 / 0 | 0 |
| 30일 전~이번 주말, 기존 서울 지역코드 1 | 0 / 0 | 0 |

전국 응답에는 서울 주소 행사 24건이 있었고 `areacode`는 비어 있었다. 이번 응답에서 기존 지역코드 필터가 후보를 누락시켰다. 이는 `areaCode2` 등 모든 기존 오퍼레이션의 폐기 확인은 아니다. 별도 일일 API 감시를 반복하지 않았다.

주말만 조회해도 1월·5월에 시작한 장기 행사가 포함됐다. 따라서 “검색 시작일보다 먼저 시작한 행사는 무조건 빠진다”는 초기 가정은 이번 응답과 맞지 않는다. 응답의 개최기간을 직접 재검사한다. 예전 홈·축제 목록은 과거 기간을 조회한 뒤 종료일을 대조하지 않아 종료 행사가 남을 수 있었고, 첫 50~100개 뒤의 행사도 놓칠 수 있었다.

공식 서비스·응답 오류 안내는 [공공데이터포털의 한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15101578)를 확인했다. 위 수치는 공식 설명에서 추정한 값이 아니라 실제 API 관측이다.

## 2. 구현

- `festival-data.ts`: 코스·홈·축제 화면의 주말 조회와 기간·좌표 검사 통일. 구 지역코드 대신 실제 좌표 사용, 중복·잘못된 날짜·좌표·종료·미래 행사 제외, 거리순 정렬.
- 페이지당 200개·최대 3페이지(600개). 뒤 페이지 실패나 상한 도달은 부분 조회, 첫 페이지 실패는 오류다. 전국 모든 행사 수집을 보장하지 않는다.
- 코스에는 반나절 15 / 하루 30 / 여유롭게 25 / 1박2일 50km 안의 가까운 축제 최대 6개만 전달한다. 해당 행사에 `detailIntro2`를 최대 6회 추가 조회하여 `playtime` 원문을 보강한다. 요금인 `usetimefestival`을 시간으로 쓰지 않는다.
- 프롬프트·최종 장소에 행사시간 원문 전달. 단순 시간 충돌은 경고하며 복합 회차·운영 요일·예약은 확인 필요로 표시한다. 기간 안이라고 매일 열린다고 단정하지 않는다.
- `tour-api.ts`: HTTP 200이어도 기관 오류·잘못된 본문은 실패 처리. 기관 오류 메시지의 키·URL을 그대로 로그로 전파하지 않는다.
- 축제 API 장애는 503/no-store. UI는 오류·재시도 / 부분 조회 / 정상 빈 결과를 구분한다. 취소된 요청의 늦은 응답을 무시한다. 오류 시 상단도 ‘0개’ 대신 ‘조회 미확인’이다.
- 모바일 필터·정렬 두 줄 배치, 주요 필터 조작 44px 이상, KST 날짜·직선거리 표기. 육안 검사에서 발견한 정렬 화살표 위치도 수정했다.
- 화면에서 사용하지 않던 축제 AI 요약 제거: 축제 탭 최대 10회, 홈 축제 분기 최대 6회의 생성 가능 경로를 제거했다. 전체 홈 AI를 없앤 것은 아니며 관광지 추천 설명은 유지한다.

## 3. 신규 AI 실측 3조건

`node scripts/verify-live-course.mjs --festival`로 개인정보 없는 합성 조건을 실행했다. AI 전체 최대 3회, 운영 생성 엔드포인트·사용량 차감·저장·조회수 경로는 사용하지 않았다.

| 조건 | 축제 후보 → 최종 포함 | 결과 | 남은 확인 |
|---|---|---|---|
| 서울 토요일 하루·연인·문화/음식 | 6 → 3 | AI, 6곳, 17.87초, 직선 합계 1.9km | 저녁 누락, 복합 공연 회차·예약 |
| 부산 토요일 하루·친구·문화/사진 | 3 → 0 | AI, 6곳, 19.56초, 16.5km | 축제를 강제로 넣지 않음. 시간 겹침 보정 후 구성 검사 통과 |
| 전주 1박2일·가족·문화/음식 | 5 → 1 | AI, 10곳, 20.69초, 9.9km | 토요일 15시 공연 포함. 일요일 예보 미확인·예약 안내 유지 |

전주는 `전주한옥마을 전통연희 퍼레이드-노상놀이야`(2547013)를 1일차 15:00~16:00에 배치했고 원문 ‘매주 토요일 15:00~16:00’과 일치했다. 실제 숙박 후보와 다음 날 일정도 포함됐다. 예약·취소·기상에 따른 운영은 확인한 것이 아니다.

서울은 18시 공연 앞에 저녁 60분과 이동을 넣을 수 없었다. 보완 규칙은 축제를 삭제하거나 하루 예산을 늘리지 않아 저녁 누락 경고를 남겼다. `덕수궁 밤의 석조전`의 원문에는 ‘회차당 100분’이 있지만 AI 제안은 60분이다. 현재 복합 회차 파서는 이를 완전히 판정하지 못하므로 **서울 코스를 완성된 일정이라고 소개하지 않는다.** 다음 우선순위는 고정 공연 회차·체류시간과 식사 충돌 해결이다.

최종 22/22개 장소는 실제 후보 ID와 대조됐고 중복은 없었다. 원본 대조 성공과 일정의 모든 품질 검사는 별개다. 신규 3조건 모두 AI 응답은 HTTP 200이었지만 운영 성공률·P95로 일반화하지 않는다.

- 관광 91회: 90회 HTTP 200/resultCode 0000, 상세 1회 7초 TimeoutError. 해당 정보는 미확인으로 남겼다.
- 날씨 3회 HTTP 200/resultCode 00. Gemini 생성 3회·모델 목록 1회 HTTP 200. 총 98회 요청(앞선 검색조건 진단 6회 제외).
- 성공 AI 3건 토큰 합계: 입력 13,616 / 출력 7,480 / 총 21,096. 청구 금액은 확인하지 않았다.
- 첫 시도는 검증기 옵션을 반영하기 전 사용법 검사에서 중단돼 외부 요청 0회. 옵션 수정 후 위 1회를 실행했다.

git 제외된 `.scratch-live-course/` 원본: `festivals-2026-09-09T04-43-03-105Z.json`, `festivals-2026-09-09T04-43-59-587Z.json`, `report-2026-09-09T04-51-40-537Z.json`. UTC 파일명이다. 같은 주말 재검증은 아래 명령으로 AI 없이 실행할 수 있다.

```sh
node scripts/verify-live-course.mjs --festival --replay report-2026-09-09T04-51-40-537Z.json
```

## 4. 검증·제출 표현

새 회귀 테스트 33개: 지역코드 없는 응답, 후속 페이지·부분 실패·상한, 여행 길이 4종과 방문 요일, 날짜·좌표, 행사시간 원문, HTTP 200 기관 오류, 503과 정상 0건 구분.

9/9 **18:07 최종 GREEN**, 단위 테스트 **350 통과 / 기존 실연동 4 skip**, lint·프로덕션 빌드 통과, 보고서 비밀값 대조 유출 0건. 최종 화면 수정 전 13:52 GREEN 보고서도 보존했다.

모의 브라우저 검증 320·390·768·1440px 모두 통과, 56개 캡처. 축제 오류→재시도→목록·부분 조회·정상 빈 결과와 기존 코스 흐름을 확인했다. 가로 넘침·브라우저 예외 0건. 육안 확인 후 오류 상태의 ‘0개’를 ‘조회 미확인’으로 바꾸고 정렬 화살표 위치를 수정하여 다시 통과했다. 최종 이미지 경로는 `.scratch-playwright/review-2026-09-09T04-57-12-472Z/`. 모의 화면은 공모전 실데이터 제출 이미지가 아니다. 검사 서버는 종료했다.

제출서에는 “관광공사 행사 원본을 여행 날짜·좌표·시간표와 연결하고, 조회 실패와 데이터 없음, 공연 회차 미확인을 구분한다”라고 쓸 수 있다. 전주 일정과 API 원본을 함께 제시한다. 호출량이나 축제 포함 자체가 수상 점수를 보장한다고 주장하지 않는다.

## 5. 남은 순서

1. 고정 공연 회차·체류시간과 식사 충돌 해결. 복합 원문을 보수적으로 판정하고 유지할 행사를 줄이거나 사용자 선택으로 수정하는 흐름 검토.
2. 당초 24조건 실측·실제 폰 테스트는 아직 미완료다. 이번 3조건은 축제 집중 표본이다. 후보 부족은 자동 테스트로 확인했지만 실제 부족 지역 표본은 별도다.
3. 공식 기능설명서 양식·실제 배포 화면·90초 시연 준비. 배포·운영 DB·팀/계정 정보·API 키 제출·접수는 별도 확인 후 진행한다.

다른 관광 오퍼레이션의 구 지역·분류코드 의존, 실시간 영업·교통 경로·예약은 이번 수정으로 해결했다고 간주하지 않는다.
