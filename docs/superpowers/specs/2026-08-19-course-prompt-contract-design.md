## 1. 왜 고치는가 — 측정부터 했다

추측으로 프롬프트를 만지지 않기 위해 baseline 을 먼저 쟀다.

### 잘 되고 있는 것 (건드리지 않는다)

| 항목 | 지시 | 실측 |
|---|---|---|
| hook 길이 | 15자 이내 | **9~12자** ✅ |
| description | 3~4문장 | **181~208자** ✅ |
| storyArc | 3~5문장 | **225~251자** ✅ |
| 반나절 장소 수 | 3~4곳 | **3/3회 준수** ✅ |
| 하루 장소 수 | 5~7곳 | **7곳** ✅ |

글 자체는 이미 좋다. *"삐걱이는 나무 바닥 소리와 은은한 책 냄새"*, *"비 내리는 토요일 아침, 번잡한 일상을 벗어나…"* — 카피라이팅 지시는 잘 먹고 있다. **그래서 카피라이팅은 이번 범위가 아니다.**

### 🔴 실제로 깨지는 것

하루 코스 실측 출력:

```
09:00 서울도서관(14) → 10:40 일민미술관(14) → 11:50 이북만두(39)
→ 13:10 덕수궁(12) → 14:40 돌담길(12) → 16:00 한국미술관(14) → 17:35 낙동강(39)
```

**문제 1 — 카페 슬롯 누락.** 규칙은 *"하루 5~7곳: 관광지 2~3 + 점심 + 카페(14:00~15:30) + 저녁"* 인데 14:40 자리를 돌담길 산책이 차지했다.

**문제 2 — 같은 카테고리 연속.** 도서관(14) → 미술관(14). *"같은 종류를 연속 배치하면 안 됩니다"* 위반.

**문제 3 — 날씨 서술이 코스 안에서 모순.**
- 1번 `whyNow`: *"창밖으로 흐르는 빗줄기를 바라보며"*
- 2번 `whyNow`: *"습한 **한여름 무더위를 피해**"*
- 6번 `whyNow`: *"**한여름 오후의 뜨거운 열기**와 소나기를 피해"*

같은 날인데 비가 오는지 더운지 오락가락한다.

### 근본 원인

세 문제 모두 **자연어 지시로만 통제하고 검증이 없어서** 생긴다. 카테고리 밸런스 규칙은 424자나 되지만 지켜졌는지 확인하는 코드가 없고, 위반해도 그대로 사용자에게 나간다.

반면 `contentId` 유효성·시간순서·이동거리는 이미 `crossValidateContentIds`·`calculateTotalDistance` 로 **검증하고 있다.** 구성 규칙만 검증 밖에 있다.

> 요약: 지켜지는 규칙과 안 지켜지는 규칙의 차이는 **표현의 강도가 아니라 검증의 유무**다. 프롬프트를 더 세게 쓰는 것으로는 해결되지 않는다.

## 3. 설계 — 3계층

### 1층. `responseSchema` 로 구조를 계약화

**실측으로 확인했다** (`gemini-3.5-flash`, 4,883ms):

```
✅ 마크다운 펜스 없음        → parseCourseJSON 의 펜스 제거 로직 불필요
✅ stops 4개, minItems/maxItems(3~4) 준수
✅ roles: attraction, restaurant, cafe, culture — enum 강제 성공
```

주목할 점: 지금 424자를 들여 설득하던 카테고리 밸런스를 **스키마가 한 번에** 만들어냈고 카페도 빠지지 않았다.

- `SYSTEM_INSTRUCTION` 에서 출력 스키마 1,184자 삭제 → **3,126자 → 약 1,950자 (38%↓)**
- `stops` 에 duration 별 `minItems`/`maxItems` → 장소 수가 부탁이 아니라 계약
- JSON 파싱 실패 재시도 경로 제거

### 2층. `role` 필드 — 검증의 전제

🔴 **지금은 카페 검증이 원천적으로 불가능하다.** 카페와 음식점이 **둘 다 `contentTypeId: 39`** 이기 때문이다. 서버에 `classifySpotRole` 이 있지만 AI 출력에는 그 정보가 없다.

AI 가 각 stop 에 `role` 을 직접 달게 하고(enum 5종), **서버가 후보의 실제 role 과 대조**한다. AI 가 음식점을 카페라고 우기면 그것도 위반으로 잡힌다.

### 3층. `validateComposition` + 재생성 1회

```
생성 → 검증
  □ 카페 슬롯 (full_day·leisurely 에 1곳 이상)
  □ 같은 role 3연속 금지
  □ 점심 11:30~13:00 · 저녁 17:30~19:00 에 restaurant
위반 → 무엇이 왜 틀렸는지 구체적 피드백을 붙여 1회만 재생성
여전히 위반 → 그대로 내보낸다
```

**재생성 1회 제한이 설계의 핵심이다.** 반나절 18초 + 10초 = 28초, 하루 28초 + 10초 = 38초로 코스A 의 50초 타임아웃 안에 들어온다. 2회를 허용하면 타임아웃이 실재하는 위험이 된다.

그리고 **위반이 남아도 코스를 내보낸다.** 카페 없는 코스가 코스 없음보다 낫다.

### 별건. 날씨 모순

`whyNow` 지시에 *"위 날씨 정보와 모순되지 않게"* 를 명시한다. 검증까지 갈 필요는 없다고 본다 — 날씨 블록이 이미 프롬프트에 있고 연결 지시만 없었다.

## 5. 실패 처리

| 상황 | 처리 |
|---|---|
| `responseSchema` 위반 응답 | SDK 가 스키마를 강제하므로 발생하지 않아야 한다. 그래도 파싱 실패면 **기존 재시도 경로를 남겨둔다**(안전망은 지운 뒤에 아쉬워지는 법이다) |

## 7. 열린 질문

1. `minItems`/`maxItems` 를 duration 별로 다르게 주려면 스키마를 **매 요청 생성**해야 한다. 상수 하나로 못 둔다.
2. `role` 을 AI 가 달게 하면 기존 `classifySpotRole`(서버 판정)과 **두 개의 진실**이 생긴다. 대조해서 불일치를 위반으로 볼지, 서버 값을 신뢰하고 AI 값을 버릴지 결정해야 한다. → **대조 후 불일치를 위반으로 본다**(AI 가 카페를 지어내는 것을 막는 게 목적이므로).
3. 1박2일(`overnight`)은 stops 7~10 에 숙박까지 끼므로 검증 규칙이 다르다. 1차에서는 **검증 대상에서 제외**하고 관찰만 한다.
