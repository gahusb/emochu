# 진짜 갈 수 있는 코스 — 방문일·휴무일·무장애 반영

> 작성: 2026-07-31 / 승인: 사용자 (A축 = 실행 가능성, M1 기간단계 통합 · M3 배지+가산) / 범위: 코스 생성 엔진 + 위저드 기간 단계 + 결과 StopCard. 홈·축제·장소상세 화면은 범위 밖.

## 배경 / 문제

이모추는 **기분·동반자·사주**(감성 축)로 코스를 짠다. 그러나 *"그래서 실제로 갈 수 있는가"*(실행 축)는 검증하지 않는다. 코드 전수 확인 결과, **이미 받아오는 데이터를 코스 엔진이 쓰지 않고 있다**:

| 갭 | 코드 근거 |
|---|---|
| 🔴 `restdate`(쉬는날)를 **장소 상세 화면엔 이미 표시**하면서, 코스 엔진은 추출조차 안 함 | 표시: `app/api/spot/route.ts:16,27,57` · 미추출: `lib/weekend-ai.ts:726`이 `usetime`/`opentimefood`/`usetimefestival`만 뽑음 |
| 🔴 `usetime`은 뽑지만 **프롬프트 문자열로만** 전달, 코드 검증 없음 | `lib/weekend-ai.ts:479` — `운영: ${spot.usetime}` |
| 🔴 **방문 요일 개념이 없음** — `Duration`은 시간 길이만 정의 | `lib/weekend-types.ts:64` · 위저드 5단계에 날짜 입력 없음 |
| 🔴 `weatherScore`가 **토요일 강수확률만** 봄 → 일요일 방문자에게 틀린 날씨로 점수 | `lib/weekend-ai.ts:338-347` |
| 🟡 enrich 단계에 **타임아웃 가드 없음** — TourAPI 지연 시 `maxDuration=60` 전체가 위험 | `app/api/course/route.ts:518-522` (try/catch만) |

결과: 일요일 휴관인 미술관이 일요일 코스에 그대로 들어갈 수 있다. **"갔더니 닫혀 있음"은 여행 서비스에서 가장 치명적인 배신**이며, 1차 심사의 완성도(30)·최종 심사의 실용성(25)에 직결된다.

## 목표

감성 축 위에 **실행 축**을 얹어, 심사위원이 직접 눌러 "이 코스는 실제로 갈 수 있다"를 확인할 수 있게 한다. 새 컨셉 도입이 아니라 **보유 데이터를 쓰는 방향**이라 기존 서사(3축 차별화)와 충돌하지 않는다.

## 변경

### M1. 방문일 선택 (선행 필수)

`StepDuration`을 **"언제 · 얼마나"**로 확장한다. 새 단계를 만들지 않아 위저드는 5단계를 유지한다.

- `CourseRequest`에 `visitDay?: 'sat' | 'sun'` 추가 (`lib/weekend-types.ts`)
- UI: 토/일 칩 + 기존 기간 선택을 한 화면에. **`duration === 'overnight'`이면 요일 칩을 숨김**(토+일 자동, 기존 `CourseStop.day` 1/2 체계 그대로 사용)
- `weatherScore`가 `visitDay`의 날씨를 보도록 수정 (현재 토요일 고정)
- 하위호환: `visitDay` 미지정 시 기존 동작(토요일 기준) 유지 — 기존 저장 코스·직접 API 호출 보호

### M2. 휴무일·운영시간 반영 (코어)

1. **추출** — `enrichWithFacilities`(`weekend-ai.ts:704-738`)에 `restdate` / `restdatefood` 추가. 기존 `usetime` 정화 로직(HTML 제거·120자 절단) 재사용
2. **파싱** — `parseRestDate(raw: string): number[] | null` 신설 (순수 함수, 별도 모듈)
   - `"매주 월요일 휴무"` → `[1]` · `"토,일 휴무"` → `[6,0]` · `"연중무휴"` → `[]`
   - **판정 불가 시 `null`** — 빈 배열(휴무 없음)과 명확히 구분
3. **스코어링** — `scoreAndRankCandidates`에 방문일 휴무 페널티. 현재 최대 획득 가능 점수(취향35 + 동반20 + 날씨15 + 거리20 + 계절10 + 편의21 + 감정13 ≈ 134)를 **단독으로 상회하는 음수**를 부여해, 다른 조건이 아무리 좋아도 상위로 못 올라오게 한다. 후보 목록에서 제거하지는 않는다(전 후보가 휴무일 때 코스가 비는 것을 방지). **`null`이면 페널티 0**
4. **검증** — `crossValidateContentIds`(`weekend-ai.ts:634-660`) 이후 단계에서 휴무 spot 검출 → 동일 역할 차순위 후보로 교체. 교체 실패 시 제거하지 않고 경고 플래그만 부여(코스 붕괴 방지)
5. **표시** — `StopCard`에 배지: 영업 확인 시 `토 영업` / 판정 불가 시 `운영시간 확인 필요`

> **핵심 원칙 — graceful degradation**: `restdate`는 자유 텍스트다. **정보 없음 ≠ 휴무.** 파싱 실패는 감점 0·배지 "확인 필요"로 처리하고, 절대 후보에서 배제하지 않는다.

### M3. 무장애 정보 (배지 + 가산)

- **선행 discovery 태스크**: 공공데이터포털에서 "무장애정보"가 KorService2의 13개 오퍼레이션 중 하나임을 확인했고 기존 `TOUR_API_KEY`로 접근 가능한 것으로 보이나, **정확한 오퍼레이션명·파라미터·응답 필드는 실제 호출로 검증한 뒤 확정한다.** 추측으로 구현하지 않는다
- `lib/tour-api.ts`에 `detailWithTour` 추가 → **TourAPI 12번째 활용 API** (현재 11개)
- `enrichWithFacilities`에서 `detailIntro`와 **병렬 호출**(`Promise.allSettled` 패턴 유지)
- `companion === 'family'`일 때 스코어링 가산 (기존 `facilityBonus`의 유모차 +8 / 키즈 +10 체계와 정합)
- `StopCard`에 무장애 배지 (휠체어·장애인주차·유모차 대여 등 실제 응답 필드 기준)
- **위저드에 새 입력을 추가하지 않는다** — 마찰 0, discovery 실패 시 드롭 용이

### M4. enrich 타임아웃 가드 (M3의 전제)

M3로 외부 호출이 늘어나므로, enrich 단계 전체에 타임아웃을 건다. 초과 시 보강 없이 진행(기존 스코어링은 그대로 동작). `maxDuration=60` 안에서 A(50s)/B(20s) 생성 시간을 지키기 위한 안전장치.
