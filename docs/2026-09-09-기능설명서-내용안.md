# 이모추 기능설명서 — 최신 내용안 (2026-09-10 갱신)

이 문서는 **공식 양식에 옮길 내용안**이다. 제출 PDF가 아니며 접수 완료를 의미하지 않는다. [기존에 전달받은 공식 양식 링크](https://drive.google.com/file/d/1mZ5t_w0Rx21QQ5JOQ5uBMgtn0laixkAF/view?usp=sharing)의 최신 버전은 제출 전 확인해야 한다. 아래 문구는 로컬 개발 버전 기준이다. 배포 서비스와 맞는지 최종 확인 후 제출한다.

## 1. 서비스 소개

**이모추 — 이번 주말, 내 조건에 맞는 국내 여행 코스**

목적지·기분·여행 시간·동반자·취향을 선택하면 한국관광공사 관광정보를 바탕으로 AI가 주말 여행 코스를 제안하는 웹 서비스다. 관광지·식사·카페·문화시설·축제·숙박을 일정으로 묶고, 시간표와 지도, 장소 교체, 저장·공유로 여행 준비를 돕는다.

사용자가 원하면 **여행일의 오행 테마**를 더한다. 생년에서 얻은 오행과 여행 시작일의 오행을 재미용 테마로 사용하며, 직접 선택한 기분·취향·동행 조건을 바꾸지 않는다. 현실적인 조건이 우선이고, 테마는 비슷한 후보의 순위와 코스 설명 분위기에 작은 영향을 준다.

서비스 주소: https://emochu.vercel.app — 개발 변경의 배포 반영 여부는 최종 확인 필요.

## 2. 해결하려는 문제

주말 여행을 준비할 때 사용자는 장소 검색뿐 아니라 이동 순서, 식사와 휴식, 방문일 휴무, 날씨, 동반자 편의시설을 따로 확인해야 한다. 이모추는 공공 관광 데이터를 조건에 맞는 코스 초안으로 연결해 탐색과 조합 부담을 줄이고자 한다.

추천을 단정하는 대신 데이터가 확인된 부분과 확인되지 않은 부분을 구분한다. 관광정보에 원본이 존재해도 실시간 영업·예약·접근 가능성이 보장되는 것은 아니므로, 확인이 필요한 곳은 사용자가 알아볼 수 있도록 표시한다.

## 3. 핵심 기능 5개

### ① 4단계 조건 입력과 AI 코스 생성

1. 어디로·어떤 기분으로: 내 주변 또는 도시·랜덤 선택, 직접 고른 기분.
2. 선택형 오행 테마: 생년 기반의 재미용 테마. 건너뛰기 가능.
3. 언제·누구와: 반나절·하루·여유롭게·1박2일, 방문 요일·동반자.
4. 취향·편의 조건: 취향 복수 선택, 접힌 영역에서 이동·시각·청각·영유아 관련 정보 요청.

관광 후보 수집 → 상세 정보 보강 → 취향·동반자·날씨·거리·테마 점수화 → AI의 장소 선택·순서·시간·설명 생성 → 원본·방문일·일정 검사 → 결과 표시로 이어진다.

기본 A 코스만 생성하며 B 코스는 사용자가 요청할 때 만든다. AI가 실패하거나 시간 제한에 도달하면 실제 관광 후보를 활용한 규칙 기반 코스를 제공하고 생성 방식을 구분해 알린다.

### ② 날짜·원본·시간표 확인

- 관광 원본 목록의 contentId만 허용하고 제목·좌표·이미지·유형을 원본으로 복원한다.
- 방문 날짜와 축제 개최기간, 파싱 가능한 정기 휴무를 대조한다. 확인되지 않은 휴무는 영업 중으로 단정하지 않는다.
- 축제는 전국 주말 목록에서 원본 좌표·방문일로 걸러 지역코드 누락에 대응한다. 행사시간 원문을 전달하고 공연 회차·예약 미확인을 안내한다. 축제 화면은 조회 실패·부분 조회·정상 빈 결과를 구분한다.
- 명시된 공연 요일·시작 목록·회차당 체류시간을 대조한다. 운영 구간을 회차로 추측하거나 축제를 임의로 늦추지 않는다. 식사와 겹치는 선택 축제는 다른 축제를 남길 수 있고 실제 음식점 대안이 들어가는 경우에만 교체하고 이유를 보여준다.
- 실제 예보 범위가 부족하면 해당 날짜는 미확인으로 표시한다. 토요일이 확인됐다고 일요일까지 맑다고 안내하지 않는다.
- 체류시간과 직선거리 기반 이동 추정치를 검사하고 겹침을 같은 날짜 안에서 조정한다. 누락된 식사는 실제 예비 음식점 후보로 보완하고, 긴 이동 구간은 같은 역할의 가까운 후보로 교체를 시도한다. 보완한 장소와 이유를 표시한다.
- 시간 예산 초과 시 체류시간을 유지하며 대기 간격을 줄이거나 마지막 선택 관광 한 곳을 제외하는 보완을 시도한다. 최소 장소 수·식사·카페·확인된 운영시간과 전체 일정 검사를 지킬 수 있을 때만 반영하며 이유를 표시한다. 모든 일정의 자동 최적화를 뜻하지 않는다.
- 파싱 가능한 운영시간·준비시간·주문/입장 마감을 대조한다. 시간 예산·일차·접근성 정보 조건을 지킬 수 없는 보완은 하지 않고 경고한다. 실시간 영업과 실제 도로 경로를 보장하지 않는다.
- 정기휴무 요일과 제안 시각의 운영구간 대조를 분리해 표시한다. 결과 요약에 일치·불일치·미확인 개수를 공개하며, 장소 교체·순서 변경 시 이전 시각의 일치 상태는 미확인으로 되돌린다.

### ③ 접근성 정보 기반 후보 우선순위

접근성 조건을 선택하면 별도 관광 API 상품인 `KorWithService2 / detailWithTour2`를 조회한다. 선택 조건에 관한 원문이 있는 후보를 우선하고 결과에서 정보를 보여준다.

정보가 없다는 이유만으로 이용 불가라고 단정하지 않으며, 미확인 후보도 남겨 그 상태를 표시한다. 데이터가 존재한다는 것은 이용 가능 보장이 아니다. 현장 접근로·출입구·주차·시설 원문과 전화 확인을 함께 안내한다.

### ④ 여행일 오행 테마

사용자가 직접 고른 기분과 사주 테마를 분리했다. 같은 조건에서 테마의 영향은 최대 5점 수준의 작은 가산점이다. 코스 결과에서 여행 기준 날짜와 실제 테마 일치 여부를 구분해 보여준다.

이는 여행의 발견과 설명에 사용하는 문화적·오락적 장치이며 정밀 사주풀이·미래 예측·건강 효과를 제공하지 않는다. 테마를 선택하지 않아도 핵심 코스 생성 기능을 사용할 수 있다.

### ⑤ 반응형 결과·교체·저장·공유

모바일에서는 일정과 지도 보기를 전환하고 넓은 화면에서는 나란히 배치한다. 지도 로딩 실패 시 외부 길찾기를 안내하며, 장소를 다른 후보로 바꿀 수 있다.

저장에 성공한 코스는 URL로 공유한다. 서버에 저장하지 못한 결과는 임시 결과임을 알리고 사용할 수 없는 공유·편집 동작을 제공하지 않는다. 코스는 보관·만료 정책을 적용하므로 무조건 영구 보존된다고 안내하지 않는다. 로그인은 개인 보관 기능을 위한 선택 기능이다.

## 4. 한국관광공사 데이터 활용

소스 기준 **API 상품 2종 / 오퍼레이션 12개**. 12개를 서로 다른 API 상품이라고 표기하지 않는다.

| API 상품 / 오퍼레이션 | 사용자에게 제공되는 가치 |
|---|---|
| KorService2 / locationBasedList2·areaBasedList2 | 선택 도시·위치 주변의 관광지·문화시설·음식점 후보 |
| KorService2 / searchFestival2 | 방문일 개최기간에 맞는 축제 후보 |
| KorService2 / searchStay2 | 1박2일 숙박 후보 |
| KorService2 / detailCommon2·detailIntro2 | 소개·좌표·운영시간·정기 휴무·시설 정보 |
| KorService2 / detailImage2·detailInfo2 | 장소 사진과 세부 정보 |
| KorService2 / searchKeyword2 | 장소 검색 |
| KorService2 / areaCode2·categoryCode2 | 지역·분류 정보. 서비스 변경 여부 별도 점검 필요 |
| KorWithService2 / detailWithTour2 | 접근성 관련 원문 정보 및 후보 우선순위 |

공식 출처는 서비스에 `출처: ⓒ한국관광공사`로 표기한다. 기관 로고는 사용하지 않는다.

기타 활용: 기상청 단기예보(확인된 날짜만 반영), Google Gemini(코스 구성·설명), Kakao 지도·길찾기·공유, Supabase(보관·공유 데이터).

## 5. 검증 가능한 개발 성과

- 자동 단위 테스트 500개 통과, 기존 실연동 4개 skip, lint·프로덕션 빌드 통과(9/10 09:58 로컬 release-green).
- 9/10 상세 요청 중복 합치기·정상 60초 캐시·동시 4개·429 후 대기 요청 억제와 운영시간 미확인 표시를 보완했다. 고정 응답에서 동일 요청 20개를 실행 1회로 합치고, 429 상황의 대기 요청을 차단했다. 운영 절감률은 미검증이다. 4개 화면 폭의 모의 UI도 통과했으며 [상세 보완 결과](2026-09-10-상세조회-한도-운영시간-보완.md)에 근거와 범위를 기록했다.
- 서울·강릉·울릉도 × 여행 길이 4개 × 일반/가족으로 24조건의 수집·일정 검사 결과를 확보했다. AI 첫 시도는 15조건 중 3개 성공, 나머지 9조건은 호출 한도 후 규칙 전용이다. 관광 상세 조회도 429가 발생해 운영시간 95/127은 미확인이며, AI 24조건 성공이나 이용 가능 보장으로 표현하지 않는다. 시간 예산 초과 사례를 보완한 재생과 근거·한계는 [24조건 검증 결과](2026-09-09-24조건-검증-개발결과.md)에 분리 기록했다.
- 실제 관광·날씨 API와 AI로 3개 지역 조건을 수정 전후 확인. 범위·실패·원본 보고서는 [실데이터 검증 결과](2026-09-09-실데이터-검증-개발결과.md)에 기록했다.
- 첫 3개 표본의 수집·생성·검증은 약 9.2~18.6초. 배포 속도나 일반 성공률로 확대 해석하지 않는다.
- 실제 일요일 예보 범위 부족을 발견해 가짜 맑음 안내를 차단하고, 정상 숙박의 시간 초과 오탐을 수정했다.
- 기존 일정 3개를 새 AI 호출 없이 관광 원본으로 재검증했다. 강릉의 저녁을 보완했고 안동의 장소 간 직선거리 합계는 44.3→4.4km로 줄었다. 강릉은 식사 추가로 20.8→26.3km로 늘었다. 표본 한계와 실제 도로거리와의 차이는 [식사·동선 보완 결과](2026-09-09-식사-동선-보완-결과.md)에 기록했다.
- 모의 UI 검증과 실데이터 검증은 구별한다. 제출용 화면은 실제 데이터로 별도 촬영한다.
- 축제 집중 실측 3조건 중 서울·전주에 실제 행사가 포함됐다. 전주는 토요일 15시 공연·숙박·2일차 일정이 연결됐다. 서울의 저녁 누락과 공연 체류시간 문제를 발견하고, 후속 재생에서 충돌하는 축제 대신 실제 음식점을 넣어 저녁을 보완했다. 다른 축제 2곳은 유지했고 직선 합계는 1.9→2.2km다. [공연·식사 충돌 보완 결과](2026-09-09-공연-식사-충돌-보완결과.md)에 근거와 한계를 기록했다. 후속 재생은 AI 0회이며 새 프롬프트 생성 품질을 검증한 것은 아니다.

## 6. 차별성과 남은 개발

차별성은 API 호출 개수 자체보다 **공식 관광 데이터 → 개인 조건 → 검증된 코스 초안 → 사용자의 확인·편집**으로 연결한 데 있다. 오행 테마는 핵심 기능을 보완하고, 접근성·날짜·휴무·날씨의 미확인 상태를 드러내 신뢰를 높인다.

다음 개발은 한도 상태 확인 후 AI 미시도·운영시간 부족 표본 보충, AI 지연·운영 재시도 검증, 실제 교통·폰·이용자 테스트다. 상세 조회 보호는 프로세스 내부이며 계정 전체 분산 제한기가 아니다. 식사·장거리·시간 예산 보완은 한정된 후보와 규칙 안에서 구현했으며 모든 일정을 최적화하지 않는다. 아직 이용자 수·방문 전환율·지역 경제 효과·제휴·수익 성과는 검증하지 않았다. 지역 특화 여부는 기존 전국형 서비스 범위를 유지하며 임의의 제휴나 가점을 주장하지 않는다.
